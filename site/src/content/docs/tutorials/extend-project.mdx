---
title: Extend from another project
description: Extend a narrow implemented interface without inventing unsupported registries.
---

Start with parameter changes to an existing model or task.
A genuinely different substrate needs its own equation and conformance checks.

```bash
uv sync --locked --group dev
uv run pytest python/tests/test_sorn.py
```

Use this focused suite to see the software boundary for a dense model implementation.
Construction uses owned NumPy arrays and a declared random generator.
Quadrants kernels receive frozen typed ndarray bundles with fixed ranks.
Keep destination/source matrix orientation and runtime batch/node dimensions.

New model work must cover old-state ordering, threshold rules, adaptation,
reset, frozen modes, inactive slots, finite-state reporting and owned snapshots.
Warm a call before inspecting compilation or timing.

The active release has two model families and declared built-in tasks.
A generic body component system, broad node registry, evolution framework and
automatic differentiation are not implemented. Historical Julia extensions remain
at [revision d0fc756d](https://github.com/btgaskin/brainless-lab/tree/d0fc756d).

Read [the implementation exercises](/python/learning/) and
[platform limits](/platform-limits/) before proposing an extension.
