---
title: Create a reproducible profile
description: Preserve scientific settings and random identities in a portable record.
---

A profile asks how one declared composition behaves over independent blocks and trials.
It characterises that protocol; it does not establish a general capability.

```bash
uv run brainlesslab check python/plans/delayed-cue.toml
uv run brainlesslab run python/plans/delayed-cue.toml --root records
uv run brainlesslab inspect records/RECORD_ID
```

The supplied example is a bounded diagnostic. Use a task's declared scored horizon
for ordinary evaluation. Keep the seed partition, warm-up and construction scope
explicit before enlarging a run.

The composition records model, task, node count and input gain.
The evaluation records blocks, trials, horizon, warm-up and seed policy.
Execution policy records placement, memory budgets, batching and selected channels.

A complete record should expose requested and resolved configurations,
per-trial random identities, raw native outcomes and independent-block summaries.
Checksums and inspection make it reviewable. Completion does not confer confirmation.

Use sparse `probe_events` when offline decoding is required.
Each event retains task, condition, block, trial, entity, feature identity, point and tick.
Diagnostic labels remain outside the controller.
