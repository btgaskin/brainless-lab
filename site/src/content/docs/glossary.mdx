---
title: Glossary
description: Stable terms for current Python specifications, execution and evidence.
---

Use these meanings in plans, code reviews and reports. Historical pages may use
different implementation terms; their source revisions own those definitions.

## Composition and execution

<strong id="node">node</strong> — One neural unit within a selected model.
`NodeSpec` chooses the model kind and its parameters.
[Models](/benchmarks/models/) describe each mechanism.

<strong id="reservoir">reservoir</strong> — The constructed neural population,
wiring and dynamic state that receives inputs and emits activity.
[Nodes and reservoirs](/handbook/nodes-reservoirs/) owns the contract.

<strong id="composition">composition</strong> — A `CompositionSpec` selecting
node model, task, count and input gain. Execution placement is separate.

<strong id="task">task</strong> — A declared observation, action, world and scoring
contract selected by `TaskSpec`. See [tasks](/benchmarks/tasks/).

<strong id="world">world</strong> — The external task state for one trial.
Different worlds in a batch are independent slots, not a shared ecology.

<strong id="body">body</strong> — The task's sensorimotor interface. The current
package implements fixed task interfaces, not a general body-component registry.
See [bodies and interaction](/handbook/bodies-interaction/).

<strong id="agent">agent</strong> — One controller interacting with one task world.
Agents or ticks inside a world do not provide extra independent replications.

<strong id="receptor">receptor</strong> — One encoded input channel supplied to
the model. Its meaning and scale belong to the task contract.

<strong id="effector">effector</strong> — One model readout channel supplied to
the task's action rule. It is distinct from a scored outcome.

<strong id="port-width">port width</strong> — The number of input or effector
channels. Resolution checks widths before allocation.

<strong id="readout">readout</strong> — The selected-node activity mean used to
form an effector. An empty selection returns zero.

<strong id="input-gain">input gain</strong> — The nonnegative composition scale
applied after task encoding and before the model step. It is separate from
task sensory gain and model input-weight parameters.

<strong id="interaction-cycle">interaction cycle</strong> — Neural frames within
one world tick. CartPole uses 24; the other current tasks use one.

<strong id="numerical-policy">numerical policy</strong> — Arithmetic dtype,
fast-math rule, reduction order and RNG policy, declared by `NumericalPolicy`.

<strong id="execution-spec">execution specification</strong> — Backend, batching,
resource budgets, threads, cache and recording, declared by `ExecutionSpec`.
See [performance](/python/performance/).

## Repetition and randomness

<strong id="evaluation">evaluation</strong> — The repetition, construction,
seed and scoring protocol declared by `EvaluationSpec`.

<strong id="target">target</strong> — A named `EvaluationTarget` containing one
composition, controller, stream identities and any interventions.
The plan supplies its evaluation protocol.

<strong id="block">block</strong> — An independent outer repetition, normally
with one constructed wiring and several reset trials.

<strong id="trial">trial</strong> — One rollout within a block. Reversal uses a
whole multi-round session as one trial.

<strong id="horizon">horizon</strong> — Maximum world ticks in a trial, including
warm-up. Early ordinary termination may produce fewer completed ticks.

<strong id="warm-up">warm-up</strong> — Leading ticks that advance state before
scoring. It is not a neural reset and is allowed only by the relevant task protocol.

<strong id="scored-interval">scoring window</strong> — The declared part of a
trial used for the primary outcome. Reversal instead uses 16 post-change rounds.

<strong id="construction-scope">construction scope</strong> — Whether construction
is shared per evaluation, per block or per trial. Offline decoding requires block scope.

<strong id="reset-policy">full reset</strong> — Restoration of initial world and
neural state, including weights, masks, thresholds or targets and learning flags,
between trials. This is the supported trial reset.

<strong id="seed-stream">seed stream</strong> — A purpose-specific random stream
derived from declared identities and the root seed.

<strong id="seed-partition">seed partition</strong> — The declared bank for
development, calibration, training, tuning, pilot, confirmation or robustness.
Separate purposes require disjoint seeds.

<strong id="aggregation">aggregation</strong> — Combining trials within a block,
then independent block means. It does not authorise a cross-task average.
See [evaluation](/handbook/evaluation/).

## Plans and records

<strong id="operation">operation</strong> — Profile, sweep, ablation, benchmark
or calibration, represented by the shared `Plan` schema.

<strong id="operation-plan">plan</strong> — The scientific question, version,
named targets, operation, protocol, numerics and evidence state.
See [plan format](/reference/plan-format/).

<strong id="profile">profile</strong> — A one-target descriptive evaluation plan.

<strong id="sweep">sweep</strong> — A plan of explicitly declared parameter cells.

<strong id="ablation">ablation</strong> — A baseline comparison with declared
interventions. The resulting contrast is specific to that intervention and protocol.

<strong id="benchmark">benchmark</strong> — Task performance across declared cases
and references. Runtime speed is a separate measurement.

<strong id="record">record</strong> — A versioned portable bundle of request,
resolved plan, trials, seed ledger, summary, provenance and checksums.
See [records and results](/handbook/records-results/).

## Scores and evidence

<strong id="anchor">reference</strong> — A declared analytic value or measured
control used to interpret a task outcome. Its policy and provenance matter.

<strong id="floor">null mean</strong> — The analytic chance or frozen empirical
reference mean. It is not a lower bound on observed performance.

<strong id="ceiling">upper bound</strong> — The mathematical maximum used by a
task's adjustment. It is not proof that an implemented oracle attains it.

<strong id="normalised-score">null-adjusted score</strong> — `(raw - null_mean) /
(upper_bound - null_mean)`. It may be negative and is not a common competence scale.

<strong id="calibration">calibration</strong> — A frozen task-specific null
distribution or declared analytic chance, matched by protocol signature.
See [analysis](/reference/analysis/).

<strong id="decoding">decoding</strong> — Offline label recovery from recorded
activity using whole-trial fit, validation and evaluation splits. It does not
supply labels to the online controller.

<strong id="evidence-state">evidence state</strong> — Planned, exploratory,
tuned, frozen, confirmed, promoted or retired protocol status.
Execution completion does not advance it automatically.
See [experiments and evidence](/handbook/experiments-evidence/).
