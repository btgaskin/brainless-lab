A task defines observations, action timing, world updates and a native outcome.
A trial executes that opportunity in one seeded world. A batch groups compatible trials
for execution; it does not create a shared ecological population.

The active tasks are Tracking, Pong, Plank CartPole Easy, delayed cue, recall interference,
delayed XOR, evidence accumulation, context integration, temporal order and reversal
adaptation. Each has its own assumptions and limits.

## Discover a task before assembling it

```python
from brainlesslab import TaskSpec
from brainlesslab.tasks import definition, resolve

task = TaskSpec("delayed_cue", {"delays": (32,)})
print(resolve(task))
print(definition(task))
```

Expect a three-input, two-effector task with one neural frame per world tick and a
48-tick default horizon. The task's native outcome key is `recall_accuracy`.

For the complete plan contract, use:

```bash
uv run brainlesslab check python/plans/delayed-cue.toml
```

Follow [the task catalogue](/reference/core-catalog/) for other widths, cadences and
default horizons. The 64 capacity cells cover delayed cue and six additional
experimental families. They are named configurations, not 64 validated cognitive abilities.

## Interpret a world and a trial

Tracking and Pong are continuous fixed-horizon control opportunities. CartPole terminates
when its declared bounds are crossed or its step cap is reached. Binary probes finish at
the end of their response episode. Reversal adaptation is one continuous multi-round
session per trial.

A full reset starts the next trial from its initial construction. Rounds inside a reversal
session are not independently reset trials. Diagnostic labels and world snapshots do not
become online controller inputs.

## Interpret a batch

Stable stream identities derive from the scientific specification. Execution groups jobs
with compatible task family, model, port widths and numerical policy. The scheduler can
split a group into smaller admitted batches without changing those identities.

More slots may improve throughput. They do not enlarge the independent sample in an
already declared plan. Memory and recording budgets limit what can be admitted; if one
trajectory cannot fit, the runner fails before constructing its world rather than
silently reducing node count or changing the protocol.

Check trial status, realised world identities and wiring IDs when comparing batch sizes.
Exact same-policy equality is a software gate; CPU64 and Metal32 require a different
numerical qualification because their arithmetic differs.
