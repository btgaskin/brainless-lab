BrainlessLab separates what a study means from where and how it executes.

```text
NodeSpec + TaskSpec + count + input_gain
  -> CompositionSpec
CompositionSpec + stable target identities
  -> EvaluationTarget
targets + EvaluationSpec + NumericalPolicy + operation
  -> Plan
Plan + ExecutionSpec
  -> resolved protocol + bounded Quadrants runtime
completed trials
  -> native outcomes + portable records + offline diagnostics
```

`NodeSpec` names Falandays or SORN and its model parameters.
`TaskSpec` names a task and its options.
`CompositionSpec` adds node count and input gain.
`EvaluationSpec` declares independent blocks, trials, horizon, warm-up and seed partition.

`EvaluationTarget` gives a condition stable pairing, construction and mechanism identities.
`Plan` adds an operation, question, version and evidence state.
`NumericalPolicy` declares dtype, ordered reduction and the versioned RNG.
`ExecutionSpec` selects CPU or Metal, batch size, memory budgets and recording.

NumPy performs construction and offline analysis. Quadrants advances model and world state.
Returned host snapshots own their storage. Labels belong to diagnostics and never enter
the online task controller.

```bash
uv run brainlesslab check python/plans/delayed-cue.toml
```

The command resolves these layers without simulation. Continue with
[evaluation](/handbook/evaluation/) and [platform limits](/platform-limits/).
