title: System map
description: Trace a scientific question through resolution, bounded execution and inspectable results.
---

BrainlessLab separates a study's meaning from its execution placement. This lets a
declared protocol retain its identities while compatible work is divided into batches.
It does not make every backend or arithmetic policy equivalent.

```text
NodeSpec + TaskSpec + count + input_gain
    -> CompositionSpec
CompositionSpec + stable IDs + controller + interventions
    -> EvaluationTarget
targets + EvaluationSpec + NumericalPolicy + question + operation
    -> Plan
Plan -> resolve -> validated ports, defaults and horizons
Plan + ExecutionSpec -> execute -> EvaluationResult
EvaluationResult -> task_outcome / offline decode / portable record
```

## Assign one responsibility to each value

| Value | Owns |
| --- | --- |
| `NodeSpec` | Model family and local equation/construction parameters |
| `TaskSpec` | Task family and task options |
| `CompositionSpec` | Model/task combination, node count and input gain |
| `EvaluationTarget` | Stable condition ID, stream keys, controller and interventions |
| `EvaluationSpec` | Blocks, trials, construction scope, horizon, warm-up and seed partition |
| `NumericalPolicy` | Dtype, strict ordered arithmetic and versioned RNG |
| `Plan` | Targets, operation, question, version and evidence state |
| `ExecutionSpec` | Backend, admitted batching, memory, cache, threads and recording |

The resolver validates the assembled specification. Host construction creates seeded
wiring and world tapes. Quadrants advances neural and task state. NumPy performs
construction and bounded offline decoding. Returned snapshots own their host storage.

## Inspect the layers without executing

```bash
uv run brainlesslab check python/plans/delayed-cue.toml
```

Expect JSON containing the original request and resolved targets. The command does not
advance state or generate a research result. To execute, use `run` or the public
`execute` function with a reviewed execution policy.

The scheduler groups compatible task/model work and admits it against managed memory
and recording budgets. Batch slots are physical placement. They do not replace target,
block, trial, wiring or feature identity.

A result contains per-trial statuses and outcomes, block summaries and provenance.
Optional recording adds sparse probe events or development replay frames. The task's
label truth stays outside the online controller.

A complete record or a successful kernel test does not promote a study. Biological
interpretation, sealed confirmation, source conformance and backend qualification each
need their own evidence.
