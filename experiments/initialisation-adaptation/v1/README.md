# Initialisation scale and continued adaptation

Retained precursor draft. The active raw-start programme is described in
[the parent guide](../README.md). This older protocol discards warm-up and must not be
combined with the active comparison. Its files remain available to interpret earlier work.

This development study asks whether the benefit of homeostatic adaptation depends on
the initial recurrent operating range. It separates weight changes from target adaptation.
It is an internal Tracking study, not an exact replication of an external result.

## Protocol

The pilot uses the canonical 200-node Tracking preset. Recurrent weights are multiplied
by `0.01`, `0.1`, or `1.0` after initialisation. Sensory weights, topology, body and random
draws are held fixed within each paired block.

Each scale has five conditions: continuous adaptation, weight-only freezing at tick 1,
complete freezing at tick 1, weight-only freezing at tick 2001, and complete freezing at
tick 2001. Weight-only freezing preserves target adaptation. Complete freezing disables
both mechanisms. Late-freeze conditions share the continuous trajectory through tick 2000.

There are four independent development blocks with one trial each. Each trial lasts 4000
ticks and scores ticks 2001–4000. All conditions share the topology and world seed ledger
from root seed `2026091401`. The five sweeps contain 60 trials in total. Six profiles at
scales `0.1` and `1.0` reuse these blocks, adding 24 diagnostic reruns. They add no
independent evidence. No confirmation seeds are defined or used.

## Validate and execute

The checked-in TOML bundle is generated by `build.jl` through `write_experiment`.
Validate without simulation:

```bash
julia --project=. bin/brainlesslab.jl check-experiment experiments/initialisation-adaptation/v1/pilot
```

Run one sweep first to establish cost and inspect its resolved configuration:

```bash
julia --project=. bin/brainlesslab.jl run experiments/initialisation-adaptation/v1/pilot/plans/01-scale_continuous.toml --root records/initialisation-adaptation
```

The bundle can run all five sweeps and six profiles:

```bash
julia --project=. bin/brainlesslab.jl run-experiment experiments/initialisation-adaptation/v1/pilot --root records/initialisation-adaptation
```

Use a fresh output directory for a repaired protocol. Preserve failed records. Do not run
the whole bundle again merely to add the remaining operations after the first sweep.

## Analysis

The primary endpoint is the task-declared Tracking outcome over ticks 2001–4000. Retain
its key, raw value, normalised value and normalisation status from the trial tables.
Check `DONE`, resolved parameters, seed ledgers, missing trials and analysis failures.
Pair by scale, block and trial; verify world and topology seeds agree before contrasting.

For every scale, subtract the continuous condition from each frozen condition. Report
the four individual paired differences and their mean. Also report the change in this
contrast between the reference scale and each smaller scale. Four blocks are a feasibility
sample; do not use these differences to declare equivalence, an optimum or confirmation.

The start-frozen comparison tests the value of adaptation over the complete rollout.
The late-frozen comparison tests the value of continued adaptation after shared history.
The difference between weight-only and complete freezing concerns the target-adaptation
mechanism. Interpret each contrast within its scale and scored interval.

Inspect profile series for activity, heading error, visibility and target error. Retain
all four blocks when examining failures. Spectral radius and branching estimates are
exploratory descriptors, not proof of criticality or of a causal explanation for performance.
Profile reruns use the same randomised blocks and must not be pooled as extra samples.

If the pilot passes its construction, pairing and recording checks, the next decision is
whether to refine the development scale grid or design a fresh variance pilot. A claim
about general adaptation would also require changed environments or a transfer task.
Exact comparison with Marc's results requires his task, initialiser, network size, freeze
semantics, horizon and score definition.
